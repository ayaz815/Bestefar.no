## Changelog

- **2026-10-25** — BildeQuiz/BilderMusikk quizzes not opening on phones (share-link/catalog "Start Quiz"). The opening screens waited for ALL media to preload ("Om verdensrommet" = 266 MB) and phones never fire the preload events, so Start never enabled. `bestefar-image/index.html` now waits only for the first question (5s cap); `bestefar-imagemusic/index.html` keeps full preload but capped at 10s; `bestefar-image/data/screens/dynamicQuiz.html` maps the raw API data itself when nothing is cached (was "No questions found"). Tests: `node --test tests/`. **Upload needed**: those 3 files.
- **2026-10-25** — AudioQuiz player now requests fullscreen as soon as every screen loads (allowed right after tapping START, which is how the image players get in) and again on the first tap/key if the browser refused, like the BildeQuiz/BilderMusikk players (`setupAutoFullscreen()` at the very top of `bestefar-audio/data/script.js`, which all 6 audio screens load, so a later error can't skip it). Existing double-tap toggle untouched; no-op where the Fullscreen API doesn't exist (iPhone Safari). Tests: `node --test tests/*.test.js`. **Upload needed**: `bestefar-audio/data/script.js`.
- **2026-10-15** — Print and Start Quiz (see below) re-applied live, per the user's go-ahead, after being deferred earlier the same day. Backend PDF endpoint redeployed to EC2; website changes committed (still need upload, as always).
- **2026-10-15** — Print → full AudioQuiz PDF. `GET /api/forms/pdf/:id` on the **backend** generates the same 3-page PDF (title page, participant answer sheet, answer key) the generator's own "Export PDF" button already produces - ported from `frontend/src/pdf/*.jsx` to plain `React.createElement` (no JSX transpiler on the backend) at `backend/pdf/*.js`, fonts/logos copied into `backend/pdf/fonts/` and `backend/pdf/assets/`. Served `Content-Disposition: inline` so the browser's own PDF viewer handles printing - which already searches for nearby AirPrint/Mopria printers and offers a copy-count field, satisfying the client's request with zero custom printer-discovery code. Wired into both the table's PDF icon and the mobile popup's Skriv ut button, AudioQuiz only.
- **2026-10-15** — Start Quiz (mobile popup + desktop table icon). Reuses the AudioQuiz player's existing `?show=<id>` loading mechanism (`https://bestefar.no/bestefar-audio/index.html?show=<id>`) - the same trick the generator's own "Preview" button already relies on, so no new endpoint was needed. AudioQuiz only; other quiz types (BildeQuiz, TekstQuiz, BilderMusikk) still show "Kommer snart".
- **2026-10-14** — Mobile quiz-info popup redesigned to match the client's mockup: centered yellow card, "Utgitt: ..." meta line, two-line info area, Skriv ut (green) / Start Quiz (red) buttons.
- **2026-10-14** — Fixed the "Ant spørsmål" count showing wrong numbers for AudioQuiz rows (root cause: a MongoDB write bug on the backend stored `screens` as an object instead of an array - full writeup in the `backend` repo's changelog). Existing broken documents were migrated after a full DB backup.
- **2026-10-14** — Fixed generator-entered Info being silently blanked by a leftover empty row in the local `quiz_info` admin-override table - an admin override now only wins when it actually has text.
- **2026-10-14** — Removed the "Musician" field per the client's correction (duplicate of the existing "Artist Name"). Artist Name is now shown inside the quiz player itself (revealed with the answer, so it doesn't spoil the song) instead of being a separate catalog field.
- **2026-10-12** — Fixed "Åpne"/"Registrere" wrapping onto two lines: the shared `.dropdown-content a` rule had `display:block`, which always puts each link on its own line regardless of device. Changed to `display:inline-block`. (`4796149`)
- **2026-10-12** — Reverted two attempts at repositioning the mobile login dropdown (tried shrinking the key icon, then opening the menu inline beside it) back to the shared default behavior — client wanted it to behave identically to laptop, not a mobile-specific layout. (`66eb7bf`, `774371f`, `c4df18a` — net effect is `66eb7bf`)
- **2026-10-12** — Reverted the Dato column's font back to the catalog's regular font (`agency_fbregular`); a previous monospace (`Courier New`) override for digit alignment was undone per client feedback, keeping `tabular-nums` for alignment. (`b478a68`)
- **2026-10-12** — Pulled real Info/Musician text from the backend API into the catalog's (i) popup for AudioQuiz rows, instead of always showing blank. (`52b1551`)
- **2026-10-12** — Fixed a CSS ordering bug that silently hid the "AudioQuiz" title above the mobile table — a `display:none` rule was declared after the mobile media query that turned it back on, so equal-specificity cascade order was winning regardless of screen size. (`2bc3310`)
- **2026-10-12** — Mobile table spacing/margin iteration (several small adjustments converging on current values) and quiz info popup changed from click-to-open to hover-to-open. (`378c181`, `83fb3d4`, `4a2d239`, and others same day)
